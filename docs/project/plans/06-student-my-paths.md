بعد `getSession()` ثم `getUser()` لا تقبل الهوية إلا إذا تطابق المعرّفان. يبدأ فرع الدروس العام وفرع المسارات مستقلين؛ فشل أحدهما لا يخفي نجاح الآخر، وفراغ التقدم العام أو الكتالوج لا يلغي قراءة تسجيلات المالك.

يقرأ فرع المسارات جميع التسجيلات بصفحات مرتبة بـ`id` مع cursor متقدم؛ لا يعد الصفحة القصيرة نهاية، بل ينتظر صفحة فارغة متحققة. تخطّط الدالة النقية اتحاد `lessonKeys` للإصدارات المثبتة في المسارات live فقط. عند وجود مفاتيح يصدر controller استدعاء واحدًا لـ`readProgress(plan.lessonKeys)`، وتنفذ الخدمة batching/pagination داخليًا حتى اكتمال القراءة. لا استدعاء تقدم لكل مسار، ولا استخدام لقراءة التقدم العامة كضمان لاكتمال تقدم المسارات.

تستند كل نسب واكتمال المسارات إلى `lesson_progress.completed` وحده. لا تنسخ حالة تقدم، ولا يحدد تاريخ التسجيل استحقاق احتساب درس سبق إكماله. يبقى `deriveStudentProgress()` العام وقراءته وكتالوج metadata الخاص به دون تغيير: أول درس معروف غير مكتمل بحسب ترتيب القراءة السحابية لـContinue، وأول ثمانية دروس معروفة لـRecent. لا تصفية أو إعادة ترتيب بحسب عضوية مسار، ويجوز ظهور الدرس نفسه في Continue العام وContinue أحد المسارات.

## سلوك البطاقات والسجل

- يجوز وجود مسارات مختلفة متعددة live بالتوازي (`active | paused`)، مع نسخة live واحدة لكل مالك/مسار، ودون primary/focused path عالمي.
- تعرض البطاقة عنوان المسار والإصدار المثبت والحالة وعدد الدروس المكتملة/الإجمالي والنسبة وشريط تقدم متاحًا. رابط live هو `/student/study-paths/<slug>/` دون `?enrollment=`.
- `active` يعرض Continue المشتق عند وجود درس مطلوب غير مكتمل. اكتمال الدروس لا يغير lifecycle: يبقى التسجيل active وتظهر رسالة الاكتمال دون Continue.
- `paused` يبقى ظاهرًا مع تقدمه ورابط المسار، ودون Continue. لا أزرار lifecycle ولا RPCs للمسارات من لوحة الطالب؛ التفاصيل والترقية في صفحة Slice 5 الخاصة.
- يظهر `withdrawn | superseded` في disclosure «سجل تسجيلاتي» للقراءة فقط، حتى دون مسارات live. الرابط `/student/study-paths/<slug>/?enrollment=<exact-owner-uuid>` مشتق من القراءة المملوكة، ولا يشتق dashboard تقدمًا تاريخيًا. صفحة المسار الخاصة وحدها تعرض التقدم الحالي بحسب المنهج التاريخي المثبت؛ ليس snapshot عند إنهاء التسجيل.
- أثناء تحميل تقدم المسارات أو فشله تبقى التسجيلات المعروفة ظاهرة؛ لا تتحول قراءة ناقصة أو فاشلة إلى `0%`. يمكن لإعادة المحاولة قراءة الفرع المتعثر دون إخفاء الفرع الآخر.
- عند غياب الإصدار المثبت لمسار معروف يجوز عرض عنوانه ونسخته وحالته ورابط slug المتحقق فقط، دون تقدم أو Continue. غياب تعريف المسار يمنع اختراع عنوان أو slug أو رابط ويظهر رسالة محايدة.
- المجموعة الفاسدة تعطي إشعار عدم اتساق لذلك المسار ولا تختار فائزًا. صف بمالك أجنبي يفشل فرع My Paths كله مغلقًا دون عرض تفاصيل جزئية.
- لا تعرض «لا توجد مسارات منشورة بعد» اعتمادًا على الكتالوج وحده؛ يلزم نجاح قراءة المالك وعدم وجود تسجيلات، مع فراغ الكتالوج. رابط `/study-paths/` العام صالح في هذه الحالة.

## حماية الهوية والسباقات

يمسح sign-out أو تغيير الحساب حالتي الفرعين فورًا، بما فيهما بطاقات المسارات والسجل وروابط Continue وRecent القديمة. تربط generation عامة النتائج بالتحقق الحالي، وأجيال مستقلة لكل فرع تجعل أحدث إعادة محاولة هي القابلة للنشر. لا يستطيع نجاح متأخر أو خطأ متأخر العودة إلى عرض حساب آخر.

لا تلغي أحداث `TOKEN_REFRESHED` و`SIGNED_IN` للحساب المتحقق نفسه قراءاته الجارية أو تعامله كمالك جديد. الأحداث التي تستلزم تحققًا جديدًا تؤجله إلى ما بعد الخروج من auth callback. يعيد focus/pageshow التحقق والقراءة؛ يمنع dispose النشر المتأخر ويلغي المؤقت واشتراك auth ومستمعي الصفحة. أخطاء التحقق تعرض retry/login دون اتخاذ هوية session وحدها سلطة للقراءة.
