# سير العمل

## 1. البدء

1. نفّذ `git status` وتحقق من الفرع والتغييرات الموجودة.
2. اتبع ترتيب القراءة في `AGENTS.md` واختر ملف الوحدة عبر `START-HERE.md`.
3. عرّف النطاق ومعيار الاكتمال والملفات التي لن تُمس.
4. للعمل متعدد المراحل أو العابر للجلسات، أنشئ خطة من `plans/TEMPLATE.md` وعيّن حالتها `نشطة`.

## 2. التنفيذ

- اعمل على أصغر تغيير يحقق المهمة واحفظ تعديلات المستخدم غير المرتبطة.
- حدّث الخطة عند اكتمال مرحلة أو تغير افتراض؛ لا تستخدمها كسجل أوامر تفصيلي.
- وسّع القراءة عند عائق محدد فقط، ووثّق الملف الإضافي وسبب الحاجة إليه.
- افحص تكاملات الحدود عند لمس Auth أو التقدم أو ingestion أو البحث أو مزامنة upstream.

## 3. التحقق

للتغييرات الوظيفية شغّل الاختبارات الأقرب أولًا، ثم بوابات المستودع:

```sh
pnpm check
pnpm build
git diff --check
```

إذا تعذر فحص، سجّل الأمر والسبب والجزء غير المتحقق. تغييرات التوثيق فقط لا تستلزم بناء الموقع ما لم تؤثر في سلوكه، لكن `git diff --check` يبقى مطلوبًا.

## 4. المراجعة

تفحص المراجعة الالتزام بالمعمارية والأنماط الموجودة، والتكرار ونظافة الكود، وEdge Cases، والأمن خصوصًا Auth/RLS/RPC والبيانات الحساسة، واحتمالات regression، وما إذا كان التغيير قد خرج عن نطاق الخطة.

المراجع لا يصلح الكود مباشرة. إذا وجد مشكلة، يسجل:

- المشكلة.
- أثرها.
- الدليل أو الموضع.
- الإصلاح المقترح.

إذا تقرر إصلاحها، تبدأ دورة جديدة صغيرة: `PLAN → IMPLEMENT → VERIFY → REVIEW`.

## 5. تحديث السياق

- حدّث ملف الوحدة إذا تغير عقدها أو حدودها أو مخاطرها الدائمة.
- حدّث `03-CURRENT-STATE.md` فقط بما هو صحيح الآن: المنجز، الجاري/الجزئي، الخطوة التالية، والعوائق أو المخاطر النشطة.
- سجّل قرارًا معماريًا ثابتًا في `DECISIONS.md`؛ لا تضع تفاصيل الجلسة هناك.
- عند اكتمال الخطة، غيّر حالتها إلى `مكتملة` واترك نتيجة موجزة قابلة للتحقق.

## 6. التوقف أو التسليم

إذا انتهت المهمة، أبلغ بحالة Git والملفات والفحوص. إذا توقفت وهي غير مكتملة، أنشئ handoff من القالب يذكر الحالة الدقيقة، ما تغير، ما لم يُتحقق، والخطوة التالية. لا تعمل commit أو push إلا بطلب صريح.

## أدوات المطور

- `pnpm project:status`: ملخص Git والمزامنة حسب المراجع المحلية وملفات migrations المحلية، دون اتصال بالخدمات.
- `pnpm slice:verify`: تشغيل بوابات التحقق بالتتابع والتوقف عند الفشل، مع فحص علامات التعارض وأسماء ملفات الأسرار المتتبعة. يولّد البناء مخرجاته المعتادة المتجاهلة في Git.
- `pnpm slice:report`: طباعة تقرير للمراجعة وحفظه في `/tmp/alkulify-slice-report.txt`؛ شغّل التحقق قبل المراجعة النهائية.

يعمل CI تلقائيًا عند الدفع إلى `develop` وعند طلبات السحب التي تستهدفه.
