# طبقة الطالب

## الموجود

- `/student/login/`: تسجيل/إنشاء حساب بالبريد وكلمة المرور.
- `/student/auth/callback/`: إتمام PKCE وتأكيد البريد بوجهة ثابتة.
- `/student/`: التحقق من المستخدم، عرض البريد، الملف الشخصي والخروج.
- `/student/profile/`: قراءة وتعديل `display_name`.
- الصفحات `noindex` ومستبعدة من sitemap.

جدول `profiles` مرتبط بـ`auth.users` مع trigger للإنشاء وRLS للمالك. تصلح الواجهة صفًا مفقودًا لحساب قديم ضمن RLS.

تحقق 02V على Supabase المستضاف أثبت عمل Auth وtrigger وعزل RLS بين مستخدمين. grants دور `authenticated` على `profiles` محصورة في `SELECT/INSERT/UPDATE` بعد migration hardening مستقلة.

تعمل `/student/` الآن كمساحة طالب authenticated كاملة لنطاق V1: تتحقق من الجلسة ثم المستخدم، وتعرض الحساب والملف والخروج، وتقرأ تقدم الدروس السحابي المملوك للمستخدم تحت RLS. لا تعدد لوحة الطالب ظلال `localStorage` ولا تصالحها.

إذا كانت قراءة التقدم فارغة تعرض حالة الفراغ ولا تطلب metadata. وإلا تجلب كتالوجًا ثابتًا عامًا من `/student/lesson-catalog.json` من الأصل نفسه، ثم يحل view model النقي metadata ويشتق:

- Continue: أحدث درس معروف غير مكتمل وفق ترتيب النشاط السحابي، مع رابط الاستئناف الفعّال.
- Recent: حتى 8 دروس معروفة مع الحفاظ على ترتيب السحابة وحالة المكتمل/الجاري.
- المفاتيح المجهولة/القديمة: تبقى في السحابة بلا حذف أو تعديل، ولا تنشئ بطاقة مكسورة أو تعرض المفتاح الخام؛ يجوز إشعار محايد واحد.

تبقى دلالات النسبة والموضع الفعّال والرابط ملكًا لـ`student-progress` النقي. ويبقى Player وحده مسؤولًا عن حفظ تقدم الدرس ومصالحة المحلي/السحابي؛ لم تغير مساحة الطالب سلوكه.

## تقدم الدرس

- الزائر: `localStorage` بالمفتاح `alkulify:student:lesson-progress:v1` وحقل `videoId`.
- المسجل: `lesson_progress` بالمفتاح `(user_id, lesson_key)`.
- عند الدخول يدمج التقدم المحلي ثم يحذفه بعد نجاح النسخة نفسها.
- الكتابات متسلسلة في مثيل المشغل؛ RPC يستخدم `greatest` وOR ويمنع تغيير المالك.
- القيود ترفض القيم غير الصالحة والمدد فوق سنة والموضع المتجاوز للمدة.
- اختبر تدفق Player إلى Supabase فعليًا للحفظ والاستئناف والإكمال، واختبر RPC للمالك ورفض `anon` والدمج الرتيب.

يكتب `pagehide` الظل المحلي تزامنيًا بينما تظل كتابة Supabase غير متزامنة، لذلك قد يكون `localStorage` أحدث قليلًا حتى إعادة الدمج. الظل غير مفصول حسب المستخدم حاليًا؛ تبديل الحسابات على متصفح مشترك حالة طرفية مؤجلة.

## غير الموجود

لا توجد بعد مسارات دراسة أو تقدم على مستوى دورة، أو خطط/روتين يومي، أو توصيات، أو شارات/streaks، أو نسبة تقدم للمكتبة/الأرشيف كله، أو ملاحظات/محفوظات سحابية، أو دلالات reset/rewatch، أو UX خاص بتعارض الأجهزة المتعددة يتجاوز الدمج الرتيب الحالي. ولا توجد أدوار إدارية أو تفضيلات دراسة.

## قواعد التوسع

تبقى بيانات المستخدم مملوكة عبر RLS، والعلاقات التعليمية تستخدم `lesson_key`. كل مزامنة جديدة تحتاج سياسة تعارض واختبارات offline/race، ولا يصبح الحساب شرطًا لقراءة الأرشيف.

تبقى المخاطر المؤجلة كما هي: قد يكون ظل `pagehide` في `localStorage` أحدث من السحابة، والظل browser-wide غير مفصول حسب المستخدم في المتصفح المشترك، ودمج أكبر موضع رتيبًا قد لا يمثل نية الطالب بعد رجوع مقصود أو إعادة زيارة. لا تعالج مساحة الطالب V1 هذه المخاطر.
