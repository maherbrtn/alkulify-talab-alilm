# ابدأ من هنا

هذه بوابة السياق وليست وثيقة شاملة. بعد `AGENTS.md` اقرأ `03-CURRENT-STATE.md`، ثم اختر ملف وحدة واحدًا فقط من الخريطة أدناه. اقرأ خطة نشطة مرتبطة بالمهمة إن وجدت؛ لا تقرأ بقية الملفات احترازيًا.

## خريطة السياق

| نطاق المهمة | الملف المطلوب | مواضع الكود المعتادة |
|---|---|---|
| الرؤية أو ترتيب الأولويات | `00-VISION.md` أو `01-ROADMAP.md` | حسب الوحدة الناتجة |
| الحدود والبنية التقنية | `02-ARCHITECTURE.md` | `src/`, `scripts/`, `supabase/` |
| حساب الطالب والتقدم | `04-STUDENT-LAYER.md` | `src/pages/student/`, `src/lib/lesson-progress.ts`, `supabase/migrations/` |
| جلب المحتوى وبناؤه وفهرسته | `05-CONTENT-SOURCES.md` | `scripts/`, `data/` |
| مسارات الدراسة | `06-STUDY-PATHS.md` | طبقة الطالب ونموذج المسارات عند إنشائه |
| البحث أو Ask AI | `07-ASK-AI.md` | البحث والفهرسة وواجهات السؤال عند إنشائها |
| مزامنة مشروع هيثم | `08-UPSTREAM-SYNC.md` | فرق Git والملفات المشتركة المذكورة فيه |
| سبب قرار معماري | `DECISIONS.md` | الوحدة المتأثرة فقط |

اختر الوثيقة الأضيق. لا تجمع `VISION` و`ROADMAP` و`ARCHITECTURE` إلا إذا كانت المهمة نفسها تعبر هذه الحدود.

## الخطط والتسليمات

- الخطة النشطة: ملف غير القالب في `plans/` يصرّح بأنه نشط ويطابق نطاق المهمة. لا تفترض أن أحدث ملف زمنيًا هو الصحيح إذا لم يطابق المهمة.
- أنشئ خطة من `plans/TEMPLATE.md` للعمل متعدد المراحل أو الذي سيعبر جلسات.
- اقرأ handoff محددًا فقط إذا أحالت إليه المهمة أو الخطة النشطة.
- اكتب handoff من `handoffs/TEMPLATE.md` عند توقف عمل غير مكتمل أو انتقاله إلى وكيل آخر.

## عند تعارض المعلومات

تحقق بهذا الترتيب: حالة Git والكود والبيانات الفعلية، ثم migrations والاختبارات، ثم الوثائق. صحح الوثيقة المعنية بدل تعويض التعارض بقراءة المستودع كله.
